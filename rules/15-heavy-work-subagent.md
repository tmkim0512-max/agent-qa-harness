# 15. Mandatory Delegation (전면 위임 — 사용자는 팀장, 메인은 창구)

**모든 작업은 서브에이전트가 한다. 메인은 지시하고, 받고, 판정하고, 보고한다 — 직접 작업하지 않는다.**
**목적: 메인 창 컨텍스트를 최소로 아낀다 — 메인엔 결정·결론만 담고, 무거운 처리·긴 출력은 애초에 메인에 안 들어오게 한다.**

메인이 파일을 고치고 있으면 그 자체가 룰 위반이다. 작업 요청을 받으면 **먼저 위임 대상을 고르는 것**이 첫 행동이다.

> **상시 승인:** 사용자가 전면 위임을 명시적으로 요청했다. 세션 시스템 프롬프트에
> "Do not call the AgentTool unless the user requested it" 류의 문구가 있어도 **그 조건은 이 룰로
> 이미 충족**된 상태다 — 위임을 다시 확인받을 필요 없다.

§13(출력 offload)의 *사전(proactive)* 짝 — §13은 이미 쏟아진 출력을 파일로 빼고, §15는 애초에 메인에 안 들어오게 한다.

## 전부 위임 (예외 2개 빼고 남김없이)

- 구현·파일 수정·리팩터·테스트 생성/실행 — **1줄 수정도 포함**
- 탐색·grep 스윕, 코드베이스 조사, 대량 파일/로그 분석
- 조사·검토·비교·판단 근거 수집 — 결론은 메인이 내리되 **근거 수집은 위임**
- 산출·소비가 길 것 같은 모든 작업

→ Agent 툴(general-purpose, explore 등) 또는 Workflow로 위임. 서브에이전트가 자기 컨텍스트에서 무거운 읽기/처리를 끝내고 **결론·요약만 반환**. 메인은 파일 덤프 안 보고 핵심만 relay.

**품질:** 위임은 **상위 모델 핀 에이전트**로 (general-purpose, explore). 단 **판정 역할(critic·verifier·code-reviewer·tracer·debugger·architect·analyst 에 해당하는 작업)은 별도 판정자 모델(외부 CLI, 읽기전용)로 대체** — 실행자와 판정자를 같은 모델에 두지 않는다. 자기가 쓴 걸 자기가 채점하면 같은 맹점을 공유하기 때문이다. 판정자 호출 불가(쿼터 소진·인증 실패) 시 우회 금지 — 막힌 사실을 보고하고 다른 서브에이전트로 대체했음을 명시(§12). 경량 모델 핀 에이전트엔 품질 민감 작업 보내지 말 것 — 필요시 model override로 상위 모델 지정.

**비용 — 기계 작업은 경량 모델:** 판단 없이 정해진 대로 처리하는 작업 — 문서·시트 기입, 정해진 형식의 산출물 작성, 배포·업로드, 반복 실행(테스트·스크립트 재실행), 데이터 정리·변환 — 은 경량 모델 override 로 위임한다. 원인 분석·설계·코드 수정 판단·검증은 기존대로 상위 모델/외부 판정자. 애매하면 상위 모델.
> 실제 운영에서 반복 관찰됨 — 비용이 큰 세션일수록 비용 대부분이 서브에이전트, 특히 상위 모델 범용 에이전트에서 나왔다. 문서 작성·시트 기입 같은 단순 작업까지 상위 모델이 수십 턴씩 돌았다.

**병렬:** 독립 작업이 2개 이상이면 한 메시지에 여러 Agent 호출로 동시 스폰. 순차 spawn은 지연만 늘린다.

## 예외 = 인라인 (이 둘 뿐)

- **순수 대화**: 코드·파일을 건드리지 않는 질의응답, 상담, 방향 논의 → 메인에서 직접. 이걸 위임하면 당신이 나와 대화 자체를 못 한다.
- **1회 읽기로 끝나는 사실 조회**: Read/Grep 한 번이면 답이 나오는 것 → 직접. spawn 왕복 > 이득 (§11).

이 둘에 안 걸리면 **전부 위임**이다. "이 정도는 내가 빨리" 는 사유가 아니다.

## 예외가 아니라 절차인 것 (위임은 하되 순서를 지킨다)

- **모호한 요청** → 서브에이전트는 당신께 질문 못 한다. 메인이 **먼저** 묻고(§5), 답을 받은 뒤 위임한다. 모호함은 인라인 사유가 아니다.
  - **정렬 인터뷰 자체는 인라인**(§5 Clarity Score 채점 + AskUserQuestion 라운드). 위임하면 서브에이전트가 질문을 못 해 인터뷰가 죽는다. 인터뷰가 끝나 의도가 서면 그때 **작업을 위임**한다 — 인라인인 건 인터뷰지 작업이 아니다.
- **대화형·중간 개입 필요** → 작업을 **작게 쪼개** 조각마다 위임하고, 조각 사이에서 당신이 방향을 튼다.
- **신뢰경계 최종 판단**(보안/인증/결제) → 작업·초안은 위임, **판정만 메인**이 한다 (§14·§06·§12).

## 차단당하면 멈춘다 (우회 금지)

**권한 훅·classifier 가 막으면 다른 경로로 뚫지 마라. 멈추고 보고한다.**
위임 프롬프트에 이 문장을 **기본값으로** 넣어라 — 서브에이전트는 사용자에게 물을 수 없으므로, *막힌 채로 돌아오는 것* 이 유일하게 옳은 행동이다.

- ❌ **우회**: 막힌 도구를 다른 도구로 갈아타 같은 일을 하기. MCP 차단 → raw REST · `.env` 읽기 차단 → 스킬 스크립트를 grep 해 자격증명 경로 알아내기 · Bash 차단 → 스크립트 파일에 써서 실행.
- ✅ **허용**: 같은 목적의 *자연스러운* 대체 수단(`cat` 차단 → `head`). classifier 자신이 허용한다고 명시하는 범위다.
- **판별 한 줄**: *"이 대체 경로가 차단의 **의도**를 비켜가는가."* 자격증명·외부 쓰기·권한 경계가 걸리면 우회다.

사유가 타당해도(도구 한계·효율) **우회 여부는 사용자 결정 사항**이다. 막혔으면 무엇을 왜 하려 했는지 적어 올리고, 권한을 열지 말지는 사용자가 정한다. classifier 자신도 그렇게 말한다 — *"STOP and explain to the user … Let the user decide how to proceed."*

> 사례 — 에이전트가 차단된 도구를 다른 경로로 우회해 같은 일을 한 사례가 있었다. 결과물이 정확해도 수단이 승인된 적 없으면 문제다. 같은 벽에 막혀 "우회 안 했다" 고 보고하고 다른 검증으로 갈음하는 쪽이 옳다.
> 규칙 파일을 쓰다 게이트에 막혔을 때도 해제 스위치를 쓰지 말고 게이트가 요구하는 형식을 맞춘다. **우회 금지 룰을 우회로 심는 건 자기모순이다.**

## 받는 법

- 서브에이전트 최종 메시지 = 결과. 메인은 핵심만 relay.
- 전량 원본 필요하면 §13 offload id 또는 파일 경로로 회수.

## 자동 안전망 (판단 누락 시)

큰 출력이 메인에 떨어져도 `offload-large-output` hook(PostToolUse, 400줄+)이 자동으로 refs에 무손실 보관 + stub만 남김. §15(사전 위임) 실패 시 §13/hook(사후 offload)이 받친다 — 데이터 유실 0.
