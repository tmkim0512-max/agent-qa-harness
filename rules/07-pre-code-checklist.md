# 7. Pre-Code Checklist

- CONTEXT.md 존재 시 먼저 읽기
- Write 전 파일 존재 여부 확인 — 있으면 Read → Edit
- 새 파일 생성 전 `git ls-files | grep <이름>` — 유사 파일 탐색
- 비슷한 기능이 있을 것 같으면 먼저 Grep

## 하네스 자산 승격 사다리 (훅/룰/스킬/스크립트를 새로 만들기 전)

```
결정론 훅으로 되나?  → 훅. 룰 안 쓴다
  안 되면 → 룰로 되나?  → 룰. 스킬 안 만든다
    안 되면 → 그제서야 스킬
```

근거: 공식 문서 — *"Unlike CLAUDE.md instructions which are advisory, hooks are deterministic and guarantee the action happens."* 산문은 지켜지길 바라는 것이고 훅은 지켜지는 것이다.
실제 운영에서 반복 관찰됨 — 기존 규칙의 상당수가 **이미 있는 게이트를 산문으로 중복**하고, 일부는 **존재하지 않는 게이트를 인용**한다. 낮은 칸으로 되는 걸 높은 칸에 만들면 그만큼 상시 로드 예산만 태우고 검증은 안 된다.
배출(안 쓰는 자산 정리)은 별도 GC 절차 — 만드는 사다리의 짝인 지우는 장치. (이 저장소에는 미포함)

**경계 — 중복 아님**: §19 ponytail 사다리는 *코드* 사다리(YAGNI→재사용→stdlib→네이티브→…), 이건 *하네스 자산* 사다리(훅→룰→스킬). 층위가 다르다.
