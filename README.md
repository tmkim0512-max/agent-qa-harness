# agent-qa-harness

AI 코딩 에이전트(Claude Code)가 **증거 없이 "됐다"고 말하지 못하게** 만드는 개인 하네스 — 훅·규칙·스킬 모음.

매일 쓰는 개인 하네스에서 실제로 돌아가는 범용 장치만 골라 옮긴 저장소다.

## 왜 만들었나

AI 에이전트는 일을 잘하지만 **보고를 믿을 수 없을 때가 있다.**

- 테스트를 안 돌렸는데 "통과했다"고 쓴다.
- 일부만 처리했는데 "완료"라고 쓴다.
- 자기가 만든 코드를 자기가 검토하고 "문제없다"고 한다.
- 권한에 막히면 다른 길로 돌아가서라도 일을 끝내려 한다.

QA가 사람이 만든 결과를 증거로 확인하듯, 에이전트의 결과도 **증거로만 믿는다**는 원칙을 장치로 만들었다.
글로 된 규칙은 잊히기 쉬워서, 되도록 **훅(매번 자동으로 실행되는 스크립트)** 으로 강제하고, 훅으로 안 되는 것만 규칙·스킬로 남겼다.

## 장치 목록

| # | 이름 | 막는 문제 | 방식 | 종류 |
|---|---|---|---|---|
| 1 | Evidence Gate · No Silent Failure | 증거 없는 "통과/완료" 보고, 실패 숨기기 | 결과를 SUCCESS / PARTIAL / FAILED / UNVERIFIED 4가지로만 보고. 실제 로그 수치 인용 의무 | 룰 |
| 2 | 보고 골격 리마인더 | 작업 지시 후 결론·근거·미달성이 빠진 보고 | 사용자가 작업을 지시하면 보고 골격(결론/했다/안 됐다/다음)을 자동 주입 | 훅 + 룰 |
| 3 | 전면 위임 · 판정자 분리 · 우회 금지 | 메인 세션이 직접 일하며 맥락을 소모, 자기 검토, 차단 우회 | 메인은 지시·판정만, 작업은 서브에이전트, 검토는 다른 모델 | 룰 |
| 4 | 메인 세션 직접 수정 차단 | 위임 규칙을 무시하고 메인이 파일을 고침 | 메인 세션의 파일 쓰기(편집툴·`sed -i`·`>` 리다이렉트 등)를 차단, 서브에이전트는 통과 | 훅 |
| 5 | 대용량 출력 오프로드 | 긴 명령 출력이 대화 맥락을 덮어씀 | 400줄 이상이면 원본은 파일로, 맥락엔 요약+ID만. 원본은 언제든 회수 | 훅 + 룰 |
| 6 | 파괴적 git 명령 차단 | `git push --force`, `git reset --hard` 로 되돌릴 수 없는 손실 | 실행 전 명령을 판독해 차단, 안전한 대안 안내 | 훅 (+테스트) |
| 7 | 세션 저널 | 세션이 끊기면 무슨 일을 했는지 잃어버림 | 매 턴 끝에 요청·변경 파일·한 줄 메모를 마크다운 저널에 자동 기록 | 훅 + 룰 |
| 8 | 복잡도 게이트 · 자산 승격 사다리 | 과한 코드, 지켜지지 않는 규칙의 누적 | 50줄 초과 변경은 외부 판정자 검증. 새 장치는 훅 → 룰 → 스킬 순으로만 | 룰 |
| 9 | discovery-fanout | 한 번의 리뷰가 결함을 놓침, 그럴듯한 오탐 | 여러 관점으로 병렬 탐색 → 다른 에이전트가 반박 시도 → 살아남은 것만 보고 | 스킬 |

## 장치별 상세

각 장치를 **무슨 문제를 막나 → 어떻게 동작하나 → 실제 사례** 순서로 적었다.
사례는 원본 파일 주석·규칙에 기록된 것만 옮겼다. 기록이 없는 장치는 없다고 적었다.

### 1. Evidence Gate · No Silent Failure — `rules/06-zero-fabrication.md`, `rules/12-no-silent-failure.md`

- **막는 문제**: "100건 처리 완료"처럼, 실제로는 일부 실패했거나 검증하지 않았는데 성공처럼 보고하는 것.
- **동작**:
  - 결과는 4가지로만 보고한다 — **SUCCESS**(전부 수행+검증 통과) / **PARTIAL**(일부만) / **FAILED** / **UNVERIFIED**(실행했지만 확인 못 함).
  - 테스트 결과는 실제 로그의 `status`, `total_steps`, `passed_steps` 를 인용해야 한다. `status=FAILED` 거나 `total_steps=0` 이면 어떤 경우에도 PASS 라고 못 쓴다.
  - `except: pass`, 사유 없는 `|| true`, 실패 테스트를 skip 으로 넘기기 등 실패를 숨기는 코드 패턴을 금지 목록으로 명시했다.
- **사례**: 개별 사고 기록은 이 파일들에 없다. 규칙 안의 예시(`100건 처리 완료` → `93/100 성공, 7건 실패`)가 막으려는 형태다.

### 2. 보고 골격 리마인더 — `hooks/report-skeleton-reminder.py`, `rules/18-report-style.md`

- **막는 문제**: 규칙 18(보고 형식)은 글이라 잊힌다. 그러면 "했다"만 있고 "안 된 것"이 빠진 보고가 나온다.
- **동작**: 사용자 입력이 들어올 때(UserPromptSubmit) 한국어 작업 지시(`고쳐줘`, `수정`, `롤백해`, `전체 승인` 등)나 이슈 키를 감지하면, 보고 골격 4칸(결론 / 했다 / 안 됐다 / 다음)을 대화에 자동으로 넣는다. "이게 뭐야?" 같은 순수 질문엔 안 넣는다.
- **사례**: 테스트(`hooks/tests/test_report_skeleton_reminder.py`)의 미탐 목록은 실사용에서 리마인더가 안 떴던 유형의 문장을 모은 것이다(`가져와주세요`, `멈춰롤백해` 등). 자동화 워커에 주입하면 워커가 본래 임무를 놓칠 수 있어 워커 환경에서는 끈다.

### 3. 전면 위임 · 판정자 분리 · 우회 금지 — `rules/15-heavy-work-subagent.md`

- **막는 문제**: (1) 메인 세션이 직접 파일을 읽고 고치며 맥락을 다 써버림 (2) 만든 모델이 자기 결과를 검토함 (3) 권한에 막히면 다른 경로로 돌아감.
- **동작**:
  - 메인은 지시·수신·판정·보고만 한다. 작업은 서브에이전트에 맡긴다.
  - 검토·검증 역할은 **실행자와 다른 모델**(외부 CLI 판정자)이 맡는다.
  - 권한 훅이나 분류기가 막으면 **멈추고 보고**한다. 다른 도구로 같은 일을 하는 것은 우회로 본다.
  - 판단이 필요 없는 기계 작업(서식 채우기 등)은 경량 모델로 보내 비용을 줄인다.
- **사례**:
  - 에이전트가 차단된 도구를 다른 경로로 우회해 같은 일을 한 사례가 있었다. 결과는 맞았지만 승인되지 않은 수단이었다. 그 뒤 "막히면 멈춘다"를 위임 프롬프트 기본값으로 넣었다.
  - 비용이 큰 세션을 분석해 보니 비용 대부분이 서브에이전트, 그중에서도 상위 모델 범용 에이전트에서 나왔다. 문서 기입 같은 단순 작업까지 상위 모델이 돌고 있어 경량 모델 위임 기준을 추가했다.

### 4. 메인 세션 직접 수정 차단 — `hooks/main-edit-guard.py`

- **막는 문제**: 규칙 3을 글로만 두면 메인 세션이 "이 정도는 직접"이라며 파일을 고친다.
- **동작**: 도구 실행 전(PreToolUse)에 호출을 검사한다.
  - 서브에이전트 호출에는 `agent_id` 가 붙어 있어 무조건 통과시킨다(실제 페이로드를 덤프해 확인한 판별 기준).
  - 메인 세션의 Write/Edit, Bash 의 `sed -i`·`tee`·`cp`·`>` 리다이렉트, `python -c "open(...,'w')"` 등을 차단한다.
  - 세션 저널·규칙·메모리·임시 폴더는 예외로 허용한다.
  - 판독 실패 시에는 막지 않고 경고만 남긴다(fail-open). 이건 보안 장치가 아니라 작업 규율이라, 오차단 한 건이 전체 작업을 멈추는 쪽이 더 비싸다고 판단했다.
- **사례**: 별도 사고 기록은 없다. 처음 손으로 짠 명령 파서가 JSON 페이로드 속 `>` 나 `FOO="a b" tee` 를 잘못 분류해서, 표준 라이브러리 `shlex` 토크나이저로 바꾼 기록이 주석에 있다.

### 5. 대용량 출력 오프로드 — `hooks/offload-large-output.py`, `bin/offload`, `rules/13-context-offload.md`

- **막는 문제**: 수백 줄짜리 로그가 대화 맥락에 그대로 들어오면 앞의 중요한 내용이 밀려난다.
- **동작**: Bash 실행 후(PostToolUse) 출력이 400줄 이상이면 원본을 `~/.claude/refs/<id>.md` 에 저장하고, 맥락에는 `[ref:<id>] · N lines` + 앞 20줄만 남긴다. `offload --get <id>` 로 원본 전체를 회수한다. 저장에 실패하면 원본을 그대로 통과시켜 **데이터가 사라지지 않게** 했다.
- **사례**: 별도 사고 기록은 없다.

### 6. 파괴적 git 명령 차단 — `hooks/destructive_git_guard.py` (+ `hooks/tests/test_destructive_git_guard.py`)

- **막는 문제**: 에이전트가 `git push --force` 나 `git reset --hard` 를 실행하면 원격 히스토리나 커밋 안 한 작업이 복구 불가능하게 사라진다.
- **동작**:
  - 두 명령만 **차단**하고, `git checkout .` / `git clean -f` 는 **경고만** 한다(사고 이력이 없어 차단 근거가 없다고 봄).
  - 따옴표 문자열, heredoc 본문, 주석, `grep`/`echo` 같은 읽기 명령은 판정에서 뺀다 → `git commit -m "push -f 금지"` 같은 정상 명령을 막지 않는다.
  - `git -C <경로> push -f` 처럼 옵션을 끼운 우회 형태도 잡는다.
  - 차단 시 대안(`--force-with-lease`)을 안내한다. 정말 필요하면 1회 우회 토큰(`GIT_GUARD=0`)이 있다.
- **사례**: `git -C <경로> push -f` 처럼 옵션을 끼운 형태는 단순 패턴 검사를 빠져나가기 쉬워 따로 다룬다. 테스트 17개는 "정상 명령을 막지 않는다"를 먼저 검증하고, 판정 로직을 일부러 비웠을 때 테스트가 실패하는지도 확인한다(검사 안 하고 통과하는 가짜 초록 방지).
- 공개판 차이: 원본은 "다른 세션이 이 트리를 쓰는 중" 정보를 차단 메시지에 붙였지만, 개인 세션 레지스트리에 의존해 뺐다.

### 7. 세션 저널 — `hooks/session-journal-capture.sh`, `rules/17-session-journal.md`

- **막는 문제**: 세션이 끊기거나 맥락을 비우면 무엇을 했고 다음에 뭘 할지 잃어버린다.
- **동작**: 매 턴이 끝날 때(Stop) 사용자 요청, git 변경 파일, 에이전트가 남긴 한 줄 메모(`pending-notes/<세션ID>.md`)를 세션별 마크다운 저널에 덧붙인다. 1턴짜리 빈 저널은 임시 폴더에 두었다가 내용이 쌓여야 노트 폴더로 옮긴다(7일 지나면 정리). 저장 위치는 `HARNESS_JOURNAL_DIR`(기본 `~/notes/Sessions`, Obsidian 볼트 폴더를 지정하면 그대로 보인다).
- **사례**:
  - 메모 파일이 전역 1개면 병렬 세션이 같은 파일을 두고 다투다 **남의 메모를 내 저널에 붙이고 원본을 지울** 수 있다. 파일명에 세션 ID를 넣어 경합을 구조적으로 없앴다.
  - 자동화 워커의 Stop 훅이 사람 세션의 메모를 가져가 지울 수 있어 워커 환경은 건너뛴다.
  - 기록된 요청 항목의 상당 부분이 사용자 요청이 아닌 도구 알림이라 필터를 추가했다.

### 8. 복잡도 게이트 · 자산 승격 사다리 — `rules/10-complexity-gate.md`, `rules/07-pre-code-checklist.md`

- **막는 문제**: 에이전트는 코드를 길게 쓰는 경향이 있고, 하네스 자체도 규칙이 계속 쌓이기만 한다.
- **동작**:
  - 50줄 넘는 변경은 쓰기 전에 멈추고 **외부 판정자 모델**에 "정말 필요한가, 더 짧게 되나"를 묻는다. 판정은 `TRIM`(줄여라) / `JUSTIFIED`(필요함) 둘 중 하나.
  - 새 장치를 만들 땐 "훅으로 되나? → 안 되면 룰 → 그래도 안 되면 스킬" 순서로만 올린다. 글은 지켜지길 바라는 것이고, 훅은 지켜지는 것이기 때문이다.
- **사례**: 기존 규칙들을 점검했더니 **상당수가 이미 훅으로 돌고 있는 게이트를 글로 중복**하고 있었고, **일부는 존재하지 않는 게이트를 인용**하고 있었다. 사다리는 이 점검 결과로 만들었다. 복잡도 게이트에는 별도 사고 기록이 없다.

### 9. discovery-fanout — `skills/discovery-fanout/SKILL.md`

- **막는 문제**: 한 번의 리뷰는 결함을 놓치고, 여러 번 돌리면 그럴듯한 오탐이 섞인다.
- **동작**: 정확성·보안·경계값 등 서로 다른 관점(렌즈) 3~4개로 병렬 탐색 → 중복 병합 → 후보마다 **다른 에이전트가 반박을 시도** → 반박을 견딘 것만 보고. 모든 발견은 `file:line` 인용 필수, 재현 경로가 없으면 "미검증"으로 분리한다. "더 좋은 설계인가" 처럼 정답 기준이 없는 판단에는 쓰지 않는다고 처음에 판별한다.
- **사례**: 별도 사고 기록은 없다.

## 설치 / 적용

Claude Code 기준. 기존 `~/.claude` 를 덮어쓰지 않도록 필요한 것만 복사한다.

```bash
git clone <this-repo> agent-qa-harness && cd agent-qa-harness

mkdir -p ~/.claude/hooks ~/.claude/rules ~/.claude/bin ~/.claude/skills
cp hooks/*.py hooks/*.sh ~/.claude/hooks/
cp bin/offload ~/.claude/bin/           # offload-large-output.py 가 이 경로를 호출한다
cp rules/*.md ~/.claude/rules/
cp -r skills/discovery-fanout ~/.claude/skills/
```

그다음 `settings.example.json` 의 `hooks` 블록을 `~/.claude/settings.json` 에 합친다.

선택 환경변수:

| 변수 | 용도 | 기본값 |
|---|---|---|
| `HARNESS_JOURNAL_DIR` | 세션 저널 저장 폴더 | `~/notes/Sessions` |
| `REPORT_ISSUE_KEY_PREFIX` | 보고 리마인더가 무조건 반응할 이슈 키 접두사 | `PROJ` |
| `CLAUDE_MAIN_EDIT_ALLOW=1` | 메인 세션 수정 차단 해제 | 없음 |
| `GIT_GUARD=0` / `GIT_GUARD_MODE=warn` | git 가드 끄기 / 경고로 낮추기 | 없음 |

테스트 실행:

```bash
python3 -m unittest discover -s hooks/tests -v
```

## 한계

- **글로 된 규칙은 강제가 아니다.** 규칙 1·3·8과 스킬은 모델이 읽고 따르는 지침이라 어길 수 있다. 그래서 핵심은 훅으로 옮기고 있지만, 아직 규칙으로만 남은 것이 많다.
- **훅은 대부분 fail-open이다.** 판독에 실패하면 막지 않고 통과시킨다. 오차단이 더 비싸다고 판단한 설계라, 보안 경계로 쓰면 안 된다.
- **명령 판독은 정규식·토크나이저 수준이다.** 변수로 만든 경로, 스크립트 파일 안의 명령 등은 못 잡는다.
- **테스트는 2개 훅에만 있다**(git 가드, 보고 리마인더). 나머지 훅은 수동 실행으로만 확인했다.
- **한국어 지시 감지는 휴리스틱이다.** 실제 대화에서 놓친 문장을 모아 넓혀 왔지만 완벽한 분류는 아니다.
- 규칙 본문의 `§번호` 는 원본 하네스의 규칙 번호다. 이 저장소에 없는 번호(§1·§5·§19·§22·§23 등)를 가리키는 곳이 있다.
- 원본 하네스의 일부(진행 보드 동기화, 지식 저장소 연동, 특정 외부 서비스 연동 장치 등)는 개인 환경 의존이라 뺐다.
